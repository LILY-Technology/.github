## How we build

**Money is not a feature.** Every amount that moves is recorded twice, and an
entry that does not balance is rejected before it is written. The books and the
payout system are tested against each other, because the most expensive defect
we can ship is the two of them disagreeing about what somebody is owed.

**A silent failure is the dangerous one.** Our worst incidents were not crashes
— they were systems that worked perfectly and told nobody. So we spend real
effort on making a wrong state *visible*: a configuration screen that reads the
running process rather than the dashboard, an alert path that reports which
channel accepted it, a backup that proves it can be restored.

**We measure before we claim.** «Done» is not evidence. A row closes when a
test, a command's output or a timestamp says so.

**We write for the person who arrives next.** A comment explains why a decision
was made and what breaks without it — not what the line does.
